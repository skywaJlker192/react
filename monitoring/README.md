# Мониторинг сайтов группы

Проект модуля 3 («Несколько экранов, публикация, расписание») справочника по Angular и React
М. Н. Макарова. Многостраничное приложение на React + Vite + TypeScript, которое показывает
сайты группы на GitHub Pages и результаты их ночной проверки. Проверку выполняет GitHub Actions
по расписанию, об изменениях приходит сообщение в Telegram.

Реализованы все механизмы глав **3.1–3.4**, автоматизации **А3** («Ночная проверка сайтов
и оповещение») и обязательные требования проекта **П3**.

## Запуск на компьютере

Нужен Node.js 20.19+ (в конвейерах — Node 24, как в справочнике).

```bash
npm install
npm run dev            # http://localhost:5173/monitoring/
node scripts/check.mjs # одна проверка сайтов, дописывает public/data/results.json
npm run build          # сборка в dist
npm run lint           # проверка кода
npm run preview        # http://localhost:4173/monitoring/ — собранная версия
```

В `public/data/results.json` уже лежат 5 реальных проверок, сделанных при подготовке проекта,
поэтому сайт показывает данные сразу. После запуска ночной проверки на GitHub история
пополняется коммитами бота.

## Публикация на GitHub Pages (глава 3.3)

1. Создайте на GitHub **публичный** репозиторий с именем `monitoring` (без README и .gitignore).
2. В папке проекта:

   ```bash
   git init
   git add .
   git commit -m "Мониторинг сайтов группы: модуль 3"
   git branch -M main
   git remote add origin https://github.com/<логин>/monitoring.git
   git push -u origin main
   ```

3. В репозитории: **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Вкладка **Actions**: дождитесь зелёной галочки у «Публикация на GitHub Pages». Адрес сайта —
   в карточке задания `deploy`: `https://<логин>.github.io/monitoring/`.
5. Проверьте прямую ссылку: откройте страницу любого сайта, скопируйте адрес
   (`…/monitoring/site/git`), откройте в новой вкладке и нажмите F5 — страница должна открыться
   (Pages отвечает кодом 404 и отдаёт приложение из `404.html`).

## Сайты своей группы

Замените список в `public/data/sites.json` адресами мониторов и других сайтов однокурсников
(`https://<логин>.github.io/monitoring/` и т. п.). Не меньше пяти, у каждого короткий `id`
латиницей. Тестовый неработающий адрес («Старый проект») можно оставить — на нём видно,
как выглядит сбой. После замены запустите `node scripts/check.mjs` и отправьте изменения.

## Оповещение в Telegram (автоматизация А3)

1. Токен бота — от **@BotFather** (тот же, что в модуле 1). Номер чата — из ответа `getUpdates`.
2. В репозитории: **Settings → Secrets and variables → Actions → New repository secret**:
   - `TELEGRAM_TOKEN` — токен бота;
   - `TELEGRAM_CHAT_ID` — номер чата.
3. Проверка двумя запусками (**Actions → Ночная проверка сайтов → Run workflow**):
   - чтобы получить сообщение для снимка, добавьте в `sites.json` тестовый несуществующий
     адрес, например
     `{ "id": "monitoring-test", "name": "Проверка оповещения", "url": "https://<логин>.github.io/monitoring-test/" }`,
     и отправьте изменения. В первом запуске о нём придёт «🔴 Не открывается … · 404»
     (в журнале шага последняя строка `Telegram: 200`);
   - второй запуск — «Изменений нет, сообщение не отправлено», новых сообщений нет;
   - снимок сообщения приложите к сдаче, тестовый сайт потом уберите из списка.

Секреты в журнал запуска попадают как `***`. В коде, чате ИИ и истории Git токена быть не должно.

## Важно про results.json

После первой ночной проверки бот сам коммитит `results.json`. Поэтому работа всегда начинается
с `git pull`, а свой локально изменённый `results.json` больше не отправляйте — будет конфликт.

## Сдача (глава П3 §6)

В репозитории курса `react-kurs` создайте папку `projects/p3-monitoring` и положите туда:

- `README.md` — ссылки на репозиторий `monitoring` и на сайт + список выполненных требований

## Вопросы к защите — краткие ответы

- **Почему прямая ссылка открывается, хотя файла нет?** Pages на несуществующий путь отдаёт
  `404.html` (копию `index.html`) с кодом 404; приложение загружается, и `BrowserRouter`
  показывает нужную страницу по пути.
- **Что сломается без `basename`?** Роутер будет искать пути от корня домена: на Pages адрес
  `/monitoring/site/git` не совпадёт ни с одним маршрутом → «Страница не найдена».
  Без `base` в `vite.config.ts` ссылки на JS/CSS в `index.html` ведут в корень домена → 404
  и пустая страница.
- **Почему хук, а не props?** Данные нужны шапке и всем страницам; провайдер загружает их один
  раз, страницы читают `useMonitoring`. Вне провайдера хук бросает ошибку
  «useMonitoring вызван вне MonitoringProvider».
- **Откуда страница сайта берёт id?** Из параметра пути `/site/:id` через `useParams`.
- **Почему коммит бота не запускает публикацию?** События от `GITHUB_TOKEN` не запускают
  конвейеры (защита от бесконечных циклов). Поэтому `check.yml` сам вызывает `deploy.yml`
  заданием `publish` (`needs: check`, `workflow_call`), а `ref: main` заставляет скачать код
  уже с коммитом бота.
- **Сайт не открывается три ночи подряд — сколько сообщений?** Одно: в первую ночь изменение
  «работал → не открывается», дальше состояние не меняется. При восстановлении — ещё одно.
- **Где хранится токен?** В секретах репозитория; в шаг попадает через `env` из
  `secrets.*`, в журнале — `***`. В `check.mjs` его писать нельзя: репозиторий публичный.
- **Почему `0 21 * * *` — это полночь по Москве?** Cron в GitHub — в UTC; Москва UTC+3,
  21:00 UTC = 00:00 следующего дня по Москве.
